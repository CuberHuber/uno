# Бенчмарк-базлайн: как прогонять и что записывать

Живой прод под нагрузочный тест не ставим:
  там реальные игроки и боевые rate-лимиты.
Вместо этого бенчи гоняются локально на собранном сервере
  в прод-конфигурации (`NODE_ENV=production`, код из `dist/`),
  а результат сравнивается с зафиксированным базлайном.
Сами цифры прогонов в репозиторий не коммитятся —
  итог заносится вручную в
  [../monitoring.md](../monitoring.md), раздел «Benchmarks».

## Запуск стенда

Порт 3000 не занимаем (его использует dev-сервер пользователя);
  для стенда — свободный высокий порт, здесь 3100.

```sh
npm run build
RATE_LIMITS=off NODE_ENV=production PORT=3100 npm start -w server
```

`RATE_LIMITS=off` — только для локального стенда:
  боты создают комнаты чаще любого человека.
В проде эту переменную не ставить никогда.

## Прогон

Во втором терминале:

```sh
BASE_URL=http://127.0.0.1:3100 npm run bench:http
BASE_URL=http://127.0.0.1:3100 npm run bench:ws
```

Конфигурация, в которой снят базлайн 2026-08-19:

```sh
TABLES=5 SEATS=2 DURATION=12 BASE_URL=http://127.0.0.1:3100 npm run bench:ws
```

После прогона сервер остановить (Ctrl-C — это graceful shutdown)
  и убедиться, что порт освобождён: `lsof -ti :3100`.

## Что записывать

- Дата, машина, версия Node, коммит (`git rev-parse --short HEAD`).
- `bench:http`: req/s и p95/p99 задержки `/healthz`.
- `bench:ws`: rounds finished, actions/s, rejects,
    p95 задержки action→broadcast.
- Отклонение от базлайна:
    911 раундов за 12 с на 5 столах, 4 422 действий/с,
    p95 лага 0.5 мс, `/healthz` — 41 k req/s.

Просадка больше ~20 % по actions/s или заметный рост p95 —
  повод для флеймграфа (`npm run flame -w server`)
  до вливания изменений, а не после.
Куда писать итог: [../monitoring.md](../monitoring.md),
  строка «Baselines from …» в разделе «Benchmarks».
