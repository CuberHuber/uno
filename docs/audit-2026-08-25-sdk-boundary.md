## 1. Блокер: сервер убивается с одного кадра

Выделение пакетов замораживает границы. Эти дефекты замораживать нельзя.

### C1 · Любой сокет гасит процесс одним `joinRoom`

`server/src/sockets.ts:39-64`. Обработчик считает оба параметра гарантированными.
Socket.IO передаёт ровно тот массив аргументов, который прислал клиент, и
добавляет ack-функцию только если клиент передал колбэк.

```js
socket.emit('joinRoom')   // args = [] → p === undefined
```

`refuse()` разыменовывает `p.code` до любой проверки → `TypeError`. Socket.IO
вызывает обработчик внутри `process.nextTick` без `try/catch`
(`socket.io/dist/socket.js:689-701`). Обработчика `uncaughtException` в
`server/src` нет — проверено `grep`, ноль совпадений. Значит `exit(1)`:
**падают все комнаты на инстансе**.

Тот же класс: `playCards({ cardIds: null })` → `game.ts:128`;
`joinRoom({ code: 123 })` → `rooms.ts:33` `code.toUpperCase()`.

### C2 · `continueWithout` пишет произвольный строковый ключ в массив

`sockets.ts:108-111` → `rooms.ts:172-189` → `game.ts:295-299`.
`p.seat` объявлен `number` в `shared/src/types.ts:93` и без проверок попадает в
`room.players[targetSeat]`. `Number.isInteger` не вызывается нигде.

`continueWithout({ seat: '__proto__' })` от любого сидящего игрока:

| строка | что происходит |
|---|---|
| `rooms.ts:176` | `room.players['__proto__']` → `Array.prototype` |
| `rooms.ts:177` | `target.left` = `undefined` → проверка пройдена |
| `rooms.ts:178` | `target.connected` = `undefined` → пройдена |
| `rooms.ts:179` | `now() - undefined` = `NaN`; `NaN < 120000` = false → **пройдена** |
| `rooms.ts:182` | `target.left = true` → **запись в `Array.prototype`** |
| `game.ts:297-299` | `s.drawPile.unshift(...p.hand)`, `p.hand` = `undefined` → TypeError → C1 → выход |

Вариант без падения, с необратимым уроном: `{ seat: '1' }` в ход первого места.
Строковый индекс достаёт настоящего игрока, `removed` ставится, но сравнение
`s.turn === seat` даёт `1 === '1'` → false, и ход с удалённого места не уходит.
Дальше свои действия возвращают `bad_seat`, чужие — `not_your_turn`.
**Стол мёртв до суточной чистки** (`rooms.ts:15,236`).

### Высокий приоритет

- **H1** `sockets.ts:113-119` — `disconnect` чистит соединение, не сверяя, что
  умерший сокет и есть текущий. Переезд Wi-Fi→LTE: клиент переподключается за
  секунду, старый сокет отваливается через ~45 с и гасит уже живое место.
  Через 120 с его можно выкинуть из партии.
- **H2** `rooms.ts:155-170` — `rematch` мутирует комнату до проверки
  `not_enough_players`, и после уплотнения мест `socket.data.seat`
  (`sockets.ts:58`) указывает на чужое место. Отключение одного игрока помечает
  оффлайн другого.
- **H3** `game.ts:146,153` — `chosenColor` проверяется только на truthiness,
  `!` протаскивает любое значение в `currentColor`. `'purple'` → ни одна цветная
  карта больше не играется; при `drawToMatch` следующий добор вытягивает всю
  колоду в одну руку.
- **H4** `rooms.ts:172-189` — нет проверки фазы; на `roundEnd` победа
  засчитывается второй раз.
- **H5** `sockets.ts:39-64` — один сокет занимает все места, оставляет
  «призраков» с живым `connected` и мёртвым `socketId`; комната не чистится.
- **H6** `deck.ts:26-34` — раздача целиком определяется 31-битным seed.
  Перебор 2³¹ по своей руке и вскрытой карте раскрывает все чужие руки и
  порядок колоды. Нужен `crypto`, шов `random: () => number` уже есть.
- **H7** `server.ts:54-57` — нет `trustProxy`, лимитеры считают IP прокси.
  За прокси одиннадцатая комната в минуту на весь интернет получает
  `rate_limited`. Реальный IP уже вычисляется рядом (`sockets.ts:31-33`).
- **H8** `game.ts:104` — `structuredClone` всего состояния выполняется **до**
  валидации, а игровые действия не лимитированы вовсе.

Замечание к прежним записям: код комнаты — 5 символов из алфавита в 20 знаков
(`rooms.ts:11-12`), пространство 20⁵ = 3.2 млн. Формата `XXXX-XXXX` в коде нет,
`client/src/ui.ts:19` `fmtCode` — тождественная функция.

## 2. Что уточняется в B-012

**Нулевых полей в `GameState` пять, не шесть**: `currentColor`, `pendingDrawn`,
`catchWindow`, `winner`, `pendingDrawKind`. Шестой `null` — `Card.color`
(`shared/src/types.ts:8`), и он другой природы: это настоящее отсутствие
(у дикой карты цвета нет), а не безымянное состояние раунда. Лечится вариантным
типом, а не объектом-состоянием.

**`mustChooseColor` — мёртвое состояние.** Ни одна строка `server/src` и
`client/src` не ставит его в `true`; ветку дикого открытия удалил коммит
`53f2cab`. При этом поле остаётся в протоколе и ведёт около десяти веток
`client/src/screens/Table.tsx`. Удаление снимает поле состояния, вариант
`Action`, событие протокола, поле проекции, нулевую ветку `cards.ts:5` — и
машина состояний проектируется на четыре состояния вместо пяти.

**Каталоги остаются на стороне приложения.** `rulesCatalog.ts` и
`basicsCatalog.ts` — двуязычная проза, 198 из 324 строк `shared/src`, девять
потребителей, все клиентские, сервер не читает ни один. В игро-независимый
пакет они не идут; в SDK остаётся только форма `RuleInfo.id: keyof Rules`.

**Порядок обхода сборки.** `--workspaces --if-present` чинит перечисление, но не
порядок: замерено на npm 10.8.2 — обход идёт в порядке массива `workspaces`,
и npm ничего не обещает (топологический порядок для запуска скриптов — открытый
запрос в npm/cli, не гарантия). Настоящая гарантия — `tsc -b` и project
references: они топологические по построению. Правило: массив держим в порядке
зависимостей, гарантию даёт `tsc -b`.

**Цикл `sdk ⇄ shared`.** Возникает, если положить в SDK `views.ts`, `Phase` или
`RoomStateView`. `views.ts` остаётся на сервере — и именно он становится швом,
который позже заменяет принтер. Ловушка: тест внутри `sdk/test/`, импортирующий
`@uno/shared`, **разрешится** через подъём в корневой `node_modules`, хотя пакет
такой зависимости не объявляет.

**Ответ на открытый вопрос про принтеры.** Не `round.print(media, viewer)`:
зритель — не параметр печати, а декоратор над печатаемым объектом,
`Seen(round, seat)`, а сокрытие доходит до листьев (`Open(cards)` против
`FaceDown(cards)`). Тогда вид принтера ровно один, и предупреждение автора EO
про «больше одного принтера — плохое разделение» не срабатывает по построению.

**Самое ценное решение сверх этого — печатать `legal`.** Сейчас
`Table.tsx:333-342` и `:386-394` заново реализуют правила в браузере. Если
раунд печатает разрешённые ходы для зрителя, из клиента уходит дублирование,
из протокола уходит `isPlayable`, а расхождение правил клиента и сервера
становится невозможным.
